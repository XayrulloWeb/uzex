# Gemini: модель, резервирование и проверяемые ответы

Два ключа задаются защищёнными переменными `UZEX_GEMINI_KEY_PRIMARY` и `UZEX_GEMINI_KEY_BACKUP`. Их значения не входят в код, Git или скрипты установки. Для REST API нужен HTTPS-доступ к `generativelanguage.googleapis.com`.

## Переключение

- Сначала проверяется список доступных текстовых моделей Gemini. Предпочтительные модели можно задать в `UZEX_GEMINI_MODELS`; снятые с доступа модели не считаются доступными только по их названию.
- При 429, таймауте, сетевом сбое, 5xx, отсутствии модели или некорректном JSON выполняется следующая попытка с другой моделью.
- При 401/403 текущий ключ временно исключается и пробуется резервный.
- После неудач применяется cooldown с учётом `Retry-After`, чтобы следующие запросы не создавали шторм повторов.
- Бюджет запросов к моделям — до 70 секунд; всего endpoint — до 80 секунд. Интерфейс показывает фактически прошедшее время.
- После исчерпания доступных вариантов возвращается состояние **unavailable**, а не «данных нет». Поиск, реестр и готовые отчёты продолжают работать.
- Исключение — однозначный простой подсчёт сделок по году: он может быть выполнен локально с явно указанным локальным происхождением. Этот резерв не пытается угадывать смысл сложного вопроса.

Смена модели или ключа не гарантирует дополнительную квоту: у моделей или ключей одного проекта могут быть общие ограничения. Все резервные варианты также могут оказаться недоступны. В таком случае сервис обязан сообщить об ошибке без выдуманного ответа.

## От вопроса к фактам

1. Известные границы данных и отсутствие полей для чистой прибыли проверяются до вызова модели. Вопрос про 2027 год не превращается в нулевой оборот или статистику других лет.
2. Gemini возвращает только типизированный JSON-план. Произвольный SQL и готовый текст с числами от модели не исполняются и не показываются.
3. Явно указанный пользователем год применяется независимо от решения модели. Идентификаторы компаний, сделок, контрактов и брокеров нельзя выдумать: они должны присутствовать в запросе или его контексте.
4. Компании сверяются со справочником; неоднозначные имена требуют уточнения. Первое похожее слово не является основанием выбрать компанию.
5. SQL строится сервером из разрешённых операций и параметров. База открывается только для чтения, внешние источники отключены.
6. Валюты приводятся по курсу каждой даты, лоты учитываются, физические единицы разделяются. Средневзвешенная цена формируется из точных сумм и объёмов через Decimal.
7. Ответ формируется из результата вычисления. В нём можно открыть SQL, параметры, число учтённых сделок и источники, а результат — выгрузить в CSV.

Это снижает риск выдуманных фактов, но не является доказательством идеального понимания любых формулировок. Ошибку интерпретации вопроса проверяют отдельными эталонами и неизвестными заранее вопросами на RU/UZ.

## Статус проверки

Резервирование и вычислительное ядро проверяются с `httpx.MockTransport` и реальной базой из 500 000 строк. Симулируются 429, 401, таймауты, некорректные ответы, исчерпание всех моделей, cooldown и общий дедлайн. Эти проверки не подтверждают работоспособность конкретного реального ключа или текущую квоту Google.

Для живого теста нужны введённые в защищённые настройки значения двух секретов и применённый доступ к домену. После изменения секретов работающий процесс приложения нужно перезапустить. Затем проверяется реальный вопрос, фактическое имя модели, ответ из базы и сценарий перехода на резерв при наблюдаемом сбое.
