# UZEX: план прототипа для отбора

Это план на основе задания, README и анализа всех девяти CSV. Реализованы сайт UZEX Observatory и контур Gemini: вопрос RU/UZ → типизированный план → проверяемый SQL → ответ из фактов. Поддерживаются резервные модели и два ключа, квоты, таймауты, cooldown и ограничение времени. Реальное подключение Gemini требует заполненных секретов среды; на текущем этапе резервирование проверено имитациями ошибок, а данные — реальными вычислениями по 500 000 сделок.

## Цель и обязательные условия

Создать публичный веб-сервис без установки и регистрации. Он отвечает на русском и узбекском по реестру биржевых сделок, сообщает точные значения и показывает основания. Если данных недостаточно, агент прямо говорит об этом.

Комиссия задаёт 10 неизвестных заранее вопросов, максимум 90 секунд на ответ. Выдуманный ответ в отсутствие данных означает дисквалификацию. Оценка: 60 баллов за ответы, 20 за качество прототипа и 20 за описание решения.

Сдача: до 5 ноября 2026 года, 18:00 по Ташкенту. В форме нужны ссылка на прототип, до трёх участников, имя и телефон руководителя, описание технологий и проверки ответов. Сервис должен оставаться доступным для проверки.

## Продукт

Предлагаемое направление: **UZEX — аналитик с проверяемыми ответами**.

Главный экран: поле вопроса, переключение RU/UZ, несколько примеров запросов и честно показанный период данных. Ответ включает краткий вывод, таблицу результата и блок «На основании каких данных».

Основания ответа: источники, период, выбранные фильтры, учёт состояний, валюта, единица измерения и формула. Для точечных запросов — идентификатор сделки и связанная карточка. Для агрегатов — число вошедших строк и воспроизводимый запрос; примеры строк не должны выдаваться за доказательство полного агрегата.

Для временных рядов и рейтингов полезен график, построенный из того же вычисленного результата. Нажатие на компанию, контракт или сделку открывает её фактические реквизиты. Эти улучшения идут после точности базового ответа.

## Техническая основа

- Python + FastAPI для API и оркестрации.
- DuckDB для вычислений и объединения всех таблиц; десятичные типы для денег.
- React + TypeScript для интерфейса, таблиц и графиков.
- LLM для понимания RU/UZ и планирования запроса через доступный API. Модель не является источником чисел и названий.
- CPU достаточно для выбранной базы; обучение модели и GPU не нужны для первого прототипа.

DuckDB, FastAPI, React, TypeScript, Three.js / React Three Fiber и Motion установлены. Добавлены REST-адаптер Gemini, резервирование и AI-интерфейс с источниками. Оба переданных ключа подключены к текущему серверному процессу без записи в исходники. Запросы блокирует сетевой прокси среды до обращения к Google; успешная авторизация и ответ реальной модели не подтверждены. Публичное размещение ещё не выполнено.

## Конвейер ответа

1. Определить язык, нужный период, сущности, метрику и условия.
2. Разрешить имена через справочники и контролируемые словари: товары и их характеристики, ИНН, коды брокеров, регионы, валюты, единицы и состояния.
3. Проверить покрытие данных и наличие требуемых полей. При неоднозначности задать короткое уточнение.
4. Построить структурированный план и параметризованный SQL для поддерживаемых операций. Для более сложных вопросов рассмотреть отдельно проверяемый SQL с ограничениями таблиц, функций и времени выполнения.
5. Выполнить вычисление с доступом только на чтение; ограничить число выдаваемых строк. Запретить внешние источники и побочные действия SQL.
6. Получить типизированные факты: точные значения, единицы, валюты, фильтры и происхождение. Формировать таблицы и численные фразы из этих фактов.
7. Проверить соответствие текста фактам и показать ответ на языке вопроса. При сбое вычисления сообщить об ошибке, не выдавая её за отсутствие данных.

Чтение случайных CSV-фрагментов через LLM не подходит для сумм и рейтингов. Поиск по названиям полезен для определения сущности; расчёты выполняет база по полному отобранному множеству.

## Порядок реализации

### Этап 1. Полнота и воспроизводимый импорт

Получение всех реестров, аудит 500 000 строк и фиксация контрольных сумм завершены. Данные импортированы в типизированную DuckDB, исходные CSV сохранены в `data/raw`, метаданные импорта и SHA-256 — в `data/import-manifest.json`. Повторная установка проверяет контрольные суммы и использует готовую базу.

Критерий импорта выполнен: воспроизведены 500 000 уникальных сделок, справочники и связи. Итоговая сумма DuckDB совпала с независимым десятичным расчётом по CSV.

### Этап 2. Вычислительное ядро

Подготовить поиск сделок, карточек, участников и брокеров; фильтры по датам, товарам, регионам, состояниям и формам; суммы, количества, рейтинги, временную динамику, цены и договорные сроки. Разделить зарегистрированные объёмы, поставленные объёмы и аннулированные сделки.

Отдельно обработать смешанные валюты и единицы, средневзвешенные цены и разные товары с одинаковым ТН ВЭД. У каждого агрегата должны быть видны определение метрики и область расчёта.

Критерий: воспроизведены контрольные ответы из CSV и дополнительные случаи по новому файлу за 2025 год.

### Этап 3. Языковой агент

**Код реализован по следующему запросу пользователя.** Gemini возвращает типизированный JSON-план, не SQL и не фактический текст ответа. Сервер самостоятельно учитывает явно указанный год, проверяет сущности, выполняет разрешённые операции и показывает источники. Поиск по реквизитам остаётся отдельной автономной функцией. Подключение реальных моделей нужно проверить после ввода секретов.

Подключить доступную модель, составить контекст схемы и терминологии, научить разрешать сущности и уточнять неоднозначность. Проверить узбекскую латиницу, кириллицу, варианты апострофов, смешанные RU/UZ запросы и продолжения диалога.

Даты вроде «в прошлом году» трактовать по дате вопроса, явно показывая выбранный период. Если период не покрыт или при обновлении пропущен один из реестров, не возвращать неполную сумму как полную. Текущий набор содержит все пять годовых файлов.

Критерий: смысловые пары RU/UZ дают одинаковые отборы и факты; источники всех численных ответов проверяемы.

### Этап 4. Интерфейс

Собрать выразительный, удобный экран с чат-вводом, таблицами, источниками, карточками сущностей и уместными графиками. Во время запроса показывать фактические этапы обработки. Графики, экспорт и текст используют один вычисленный результат.

Критерий: сценарий доступен без регистрации на компьютере и телефоне; ошибки и ограничения понятны пользователю.

### Этап 5. Проверка, публикация и описание

Провести самостоятельный прогон неизвестных агенту формулировок: точечные ответы, несколько объединений, агрегаты, условия по характеристикам товаров, отрицательные вопросы и запросы с неоднозначностью. Уже подготовлены 18 эталонов на RU/UZ, включая 2025 год и весь период; дополнить их границами периода и проверкой устойчивости к недоступности LLM.

Отдельно измерить полное время ответа при параллельных запросах. Обязательное ограничение — 90 секунд; внутренний ориентир для обычных вопросов — несколько секунд, но его ещё нужно измерить.

Разместить сервис на доступном хостинге и проверить по реальному публичному адресу, без установки и регистрации. Локальный процесс и открытый порт не подтверждают публичную доступность. Подготовить описание для формы: схема данных, технология, нормализация, вычисления, защита от выдумок, методика и результаты проверок, известные ограничения.

Отправка формы, передача персональных данных и публикация проверяются отдельно по полномочиям и доступным средствам; этот план не означает, что они уже выполнены.

## Дополнительные возможности после обязательного ядра

- Объяснение изменения цены между периодами с указанием объёма выборки.
- Карточка поставщика: сделки, товарные группы, суммы, завершённые и текущие просрочки.
- Сравнение компаний или регионов с явными единицами и одинаковыми фильтрами.
- Экспорт результатов с параметрами запроса и источниками.

Не добавлять прогнозы и произвольные «оценки надёжности» без доказуемого основания. Уровень уверенности не заменяет проверку фактов.

## Что пока не подтверждено

- Живое подключение Google Gemini после ввода защищённых секретов, квоты аккаунтов и целевой хостинг.
- Точные адреса формы сдачи и исходной страницы с раскрытыми FAQ.
- Разрешено ли менять прототип после подачи: в присланном тексте соответствующий ответ FAQ был свёрнут.
- Понимание свободных формулировок реальной моделью и её фактическое время ответа: эти свойства нельзя подтвердить имитацией API. Сайт, API, расчёты и резервирование проверяются отдельно.
